# 全体レビュー

**検証用サンプルとして、IAM認証・実行権限の限定・入力検証・モデル再利用を確認しました。公開前の環境情報除去とクライアントの送信先検査を実施しました。初期化・精度・運用監視に制約が残るため、本番運用に十分な構成と断定しません。**

## 判定と対応

| 観点 | 判定 | 確認内容・対応 |
|---|---|---|
| 公開データの保護 | 対応済み | 実アカウント・接続先・資源識別子・配置先・実設定・端末情報を公開資料から除去。生の実行記録を公開対象から除外 |
| 公開対象の管理 | 対応済み | 明示的なPUBLIC_FILES.txtからのみ書き出し。秘密情報の疑い、私有パス、リンク、範囲外ファイルを拒否 |
| 署名情報の送信先 | 修正済み | 署名前にHTTPS、既定execute-apiホスト、設定リージョンとの一致、許可ルートを検証。リダイレクトも拒否 |
| API認証 | 確認済み | 推論とhealth両ルートでAWS_IAM。認証なしのルートやFunction URLを作成しない |
| Lambda実行ロール | 確認済み | 対象CloudWatchログへの書込みのみ。推論に不要なストレージ・外部AI等の権限を追加しない |
| 入力検証 | 確認済み | JSON形式・重複キー・Unicode・本文長・質問数・選択肢・token数を検査。切り捨てが必要な入力を拒否 |
| ログ | 確認済み | 本文、質問、判定結果、認証ヘッダー、例外メッセージをアプリログに記録しない。管理用ログ自体は非公開で扱う |
| モデルの再利用 | 確認済み | ハンドラー外で初期化し、実行環境内で再利用。モデル取得はビルド時のみ |
| ビルド・依存管理 | 一部対応 | モデルcommit・主要依存・CDK CLIを固定。全推移依存・OS・ベースイメージの完全なhash固定は未実施 |
| 配置先の指定 | 修正済み | アプリの固定リージョンへのフォールバックを削除。利用者のCDK設定から解決 |
| スロットル・並列数 | 検証向け | スロットルと予約同時実行を設定。性能上限・費用最適化の保証ではない |
| 初期化 | 既知の制約 | 通常起動のタイムアウトを確認。改善を目的としない検証のため未解消 |
| 判定精度 | 既知の制約 | 商品レビュー正答率56.0%。否定への偏りを記録。実用途の精度保証なし |
| 監視・ログ保持 | 本番設計が必要 | アラーム・SLO・長期負荷試験なし。既定のログ保持・削除方針は検証用途 |
| ライセンス | 未決定 | 上流の表示は記録済み。リポジトリ自身の利用許諾は権利者による決定が必要 |

送信先がAWSの既定ホストであることは、そのAPIの所有者を保証しません。自身のデプロイから得た信頼できるローカル出力だけを使用してください。

## 公開境界

公開するのは、一般化した手順、ソースコードの既定値、合成入力、期待値、実際の判定、確率、レイテンシー、集計です。実行日時・端末構成・配置先・資源の実設定・認証情報は含めません。モデル名・revisionと依存ライブラリの指定はプログラムの仕様として残します。

元の環境記録を消して測定値を書き換えることはしていません。非公開の元記録を保管し、公開対象を項目単位で抽出しています。元記録との差分は、本文・期待値・判定・正誤・レイテンシーが維持されることを確認します。

.gitignoreだけに依存せず、書き出し時に許可リストと内容検査を行います。ただし、任意の文章に紛れた機密情報を正規表現だけで完全に検出できる保証はありません。内容を確認した新規公開用フォルダーを配布し、作業フォルダー全体・非公開の元記録・既存Git履歴を持ち込まない運用とします。

## 検証範囲

今回のレビューはソース、設定、テスト、検証資料、公開用データの静的確認とローカル実行確認です。署名先検証・公開検査・一般手順を改善しました。推論モデルやデプロイ済みAWS資源は変更していません。

[検証記録](../VERIFICATION.md)にテストと文書整合性の確認をまとめています。侵入試験、全依存の脆弱性監査、コンテナイメージのCVEスキャン、IAM Access Analyzerによる実アカウントの監査、GitHubの既存履歴の監査は今回実施していません。READMEの構成図と手順はコードに照合したもので、第三者環境での新規デプロイ成功を保証しません。

## 一次情報との照合

- [AWS Lambda best practices](https://docs.aws.amazon.com/lambda/latest/dg/best-practices.html)：実行環境の再利用、最小権限、メトリクスと負荷試験の考え方を確認。
- [HTTP API quotas](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-quotas.html)：HTTP APIの統合timeout上限30秒。Lambda単独の延長では解決しないことを確認。
- [Lambda initialization lifecycle](https://docs.aws.amazon.com/lambda/latest/dg/lambda-runtime-environment.html)：通常起動とProvisioned Concurrencyで初期化の時間制約が異なるため、検証値を混同しない。
- [Lambda container images](https://docs.aws.amazon.com/lambda/latest/dg/images-create.html)：ベースイメージの更新後も、自分のイメージの再ビルド・再デプロイが必要。

既定値の妥当性は用途で変わります。これらのガイドを参照したことを、全要件への適合認証としては扱いません。
